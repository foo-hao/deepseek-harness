# Agent Note: 输入区思考强度滑块

Status: implemented

[English](2026-08-19-composer-effort-slider.md) | 中文

## Problem

输入区的模型控件把推理强度选择藏在二级菜单中：先打开模型触发器，再进入强度行，最后进入等级列表，共需三次操作；已选等级只能作为说明文字后缀挤在模型触发器中。每个会话的 `ModelDirectory` 已经以适配器提供的推理强度等级为真源，影响操作效率的只是展示方式。

## Decision

`ModelSelect` 使用模型触发器旁始终可见的离散滑块取代强度面板：一条水平轨道为适配器提供的每个强度等级设置一个档位；适配器未设置模型默认值时，还会加入提供方默认项。滑块仅在当前模型公开推理元数据时显示。指针拖动或单击以及 ArrowLeft/ArrowRight 键盘步进，都通过与模型列表相同的逐会话目录 `select` 操作提交，因此遭拒的强度选择仍会通过输入区 Toast 提示。

展示细节包括：已到达的档位显示为实心，悬停时轨道变亮，滑块圆点在悬停与拖动时依次放大，键盘焦点环与触发器一致，所有动画均受 `prefers-reduced-motion` 约束。菜单改为单层模型列表；仅由已移除面板使用的 locale 键（`trigger.ariaEffort`、`menu.model`、`action.reload`、`empty.efforts`）被删除，`menu.aria` 作为模型列表标签使用。

## Alternatives considered

- **保留可逐层进入的强度面板。** 原有方式缩小了输入区宽度，但把最常调整的会话控件藏在三次操作之后，可达性较差。
- **在模型菜单内使用单层单选组。** 这比面板少一次操作，但强度仍藏在触发器之后，已选等级也无法一眼看到；滑块会始终显示该等级。
- **文本选择器或分段控件。** 第二个下拉框仍存在同样的隐藏交互问题；分段控件无法容纳适配器声明的等级数量，其范围可能从一个等级到多个等级，还可能包含提供方默认项。

## Consequences

触发器标签不再携带强度；滑块的 `aria-valuetext` 与数值标签负责展示当前等级。模型控件锁定时，滑块不可交互且不能获得焦点；模型没有推理元数据时，滑块完全不显示。强度功能本身保持不变，包括适配器提供的等级、提供方默认值和逐模型默认值，并与上游行为一致；变化仅限于 Web 展示。

## Testing

`ui-model-selection/tests/model-select.client.spec.tsx` 直接驱动滑块，覆盖已提交档位、键盘步进、提供方默认位置、锁定态不可交互、拒绝 Toast，以及没有推理元数据时不显示。无密钥 Web 场景 `apps/web/tests/declared-reasoning.e2e.ts` 将滑块步进到声明的等级，并重新记录其 ARIA 预期输出。
