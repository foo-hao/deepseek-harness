# Agent Note: 将会话迁移到其他工程

Status: implemented

[English](2026-08-18-session-project-relocation.md) | 中文

## Problem

会话归属于其规范工作目录所标识的工作区。工作区浏览器可以分叉、重命名或归档会话，但无法把已有对话迁入当前工作实际所属的工程。新建替代会话会丢失现有对话分支，继续把原会话留在原处又会让工作区列表无法准确反映归属关系。

## Decision

会话迁移复用现有分叉扩展点，并增加可选的目标工作目录。主机将目标解析为规范工作区，按需创建工作区，并把目标目录写入子会话头。客户端运行时通过会话管理器传递该覆盖值；工作区行操作先打开工程选择器，再请求分叉。

子会话在目标工程成功打开后，源会话随即归档。该流程在交互上体现为“移动”，同时保留原始事件日志，并可通过现有取消归档路径恢复。分叉失败时，源会话保持活动和选中状态。

## Alternatives considered

- **改写源会话头。** 会话身份与重放依赖不可变会话头，原地改变工作目录会削弱持久化保证。
- **直接复制持久化文件。** 文件级复制会绕过已经负责分叉语义的会话服务、工作区解析和存储后端。
- **分叉后让两个会话都保持可见。** 这样可在主列表保留两个分支，但会把迁移表现为重复项，并使源工程继续堆积无效归属。

## Consequences

迁移后的对话在目标工程中获得新的会话标识符，已归档的源会话仍可恢复。标题递增行为沿用正常分叉路径。工作区解析继续由主机负责，界面只提供目标目录并协调成功后的交接。

## Testing

工作区行测试覆盖新的移动操作，并确认不会同时打开源会话。运行时与主机契约覆盖可选工作目录覆盖值，工作区浏览器夹具包含迁移回调。归档步骤只在目标会话创建并打开成功后执行。
